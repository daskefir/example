# Shade: анонимный мессенджер на Solana

Мобильное приложение для iOS и Android на Expo / React Native. Сообщения шифруются
сквозным шифрованием и передаются через блокчейн Solana. Своих серверов у приложения нет.

## Как это устроено

| Что | Как |
|---|---|
| Регистрация | Нет телефона, email и аккаунта. На устройстве генерируется случайный 32-байтный seed. |
| ID пользователя | Публичный ключ ed25519 в base58. Им делятся с собеседником. **В блокчейн ID не попадает.** |
| Шифрование | X25519 + XSalsa20-Poly1305 (`nacl.box`) с одноразовым эфемерным ключом на каждое сообщение. |
| Подлинность | Внутри шифротекста лежит подпись ed25519 отправителя. Она связывает отправителя, получателя, время и текст. |
| Скрытый отправитель | ID отправителя находится только внутри шифротекста (sealed sender). |
| Доставка | Одна транзакция Solana: перевод 0 lamports на «адрес входящих» получателя (хеш его ID) и SPL Memo с конвертом. |
| Комиссия | Платит отдельный «кошелёк для комиссий», выведенный из seed. В блокчейне он никак не связан с ID. |
| Хранение ключа | iOS Keychain / Android Keystore (`expo-secure-store`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`). |
| Длина текста | До 400 байт UTF-8. Шифротекст дополняется до блоков по 64 байта, чтобы скрыть точную длину. |
| Модерация (App Store 1.2) | Условия использования при входе, запросы от незнакомых ID, блокировка, «пожаловаться» (блок + удаление). |

Формат конверта описан в `src/lib/envelope.ts`, логика блокчейна в `src/lib/solana.ts`,
ключи в `src/lib/identity.ts`.

### Что видно в блокчейне

Видно: время, адрес кошелька для комиссий и адрес входящих получателя. Кто знает ID
получателя, может вычислить его адрес входящих и посчитать, сколько сообщений ему пришло.
Не видно: текст, ID отправителя и ID получателя.

### Ограничения, о которых нужно знать

- **Пополнение кошелька.** Если пополнить кошелёк для комиссий с биржи, где пройдена
  верификация (KYC), отправитель связывается с личностью. Пополняйте из анонимного источника.
- **RPC-провайдер** видит IP-адрес и то, какой адрес входящих опрашивается. Укажите свой узел
  в настройках (на mainnet это в любом случае нужно: публичный RPC сильно ограничивает запросы).
- **Нет forward secrecy.** Если seed утечёт, можно расшифровать всю историю из блокчейна.
  Следующий шаг: ротация ключей или протокол Double Ratchet.
- **Сообщения вечные.** Удалить их из блокчейна нельзя, можно только с устройства.
- **Опрос вместо push-уведомлений.** Сообщения проверяются раз в 15 секунд, пока приложение
  открыто. Для push нужен свой сервер-наблюдатель, а он ухудшит анонимность.
- **Локальная история** лежит в AsyncStorage в открытом виде (её защищает шифрование
  устройства iOS). Можно добавить шифрование ключом из Keychain.
- **Аудита безопасности не было.** Перед релизом с реальными пользователями нужен
  независимый аудит.

## Запуск

```bash
npm install
npm test            # юнит-тесты протокола
npm run typecheck
DEVNET=1 npm test   # реальная отправка через Solana devnet (нужен интернет)
```

В приложении есть нативные модули (secure-store и др.), поэтому нужен development build,
а не Expo Go:

```bash
npx eas-cli@latest build --profile development --platform ios
npx expo start --dev-client
```

По умолчанию используется **devnet**. В настройках есть кнопка «Получить 1 тестовый SOL».

## Публикация в App Store

Нужны: аккаунт Apple Developer ($99 в год) и аккаунт Expo. Mac не нужен, сборка идёт в облаке EAS.

1. В `app.json` замените `ios.bundleIdentifier` (`com.example.shade`) и при желании название.
   Для публикации нужны собственные иконка и splash: сейчас стоят заглушки шаблона.
2. `npx eas-cli@latest build --platform ios --profile production`
3. `npx eas-cli@latest submit --platform ios`
4. В App Store Connect:
   - **Экспорт шифрования.** Приложение использует сквозное шифрование
     (`usesNonExemptEncryption: true`). Вам ответят на вопросы о шифровании. Для стандартных
     алгоритмов обычно подходит освобождение mass market (категория 5A992), но после него
     нужно подать в BIS ежегодный отчёт о самоклассификации. Проверьте требования для своей юрисдикции.
   - **Privacy Nutrition Label:** «Data Not Collected». Манифест приватности уже есть в `app.json`.
   - **Возрастной рейтинг:** у приложения есть пользовательский контент и неограниченное
     общение, поэтому ставьте 17+ или следуйте анкете.
   - **Review Notes:** объясните, что это мессенджер без сервера, и приложите два тестовых ID
     с историей на devnet, чтобы ревьюер мог проверить чат, блокировку и жалобу.
   - **Ссылки на политику конфиденциальности и условия:** нужны публичные URL.
5. Криптовалюта в приложении. Пользователь только пополняет свой кошелёк для комиссий
   извне, приложение не продаёт и не обменивает криптовалюту. Это соответствует
   пункту 3.1.5 правил App Store. Встроенный обмен или покупка SOL потребуют отдельной проверки.

## Структура

```
index.ts                  точка входа (полифилы, затем expo-router)
src/lib/identity.ts       seed → ID, ключ шифрования, кошелёк для комиссий, адрес входящих
src/lib/envelope.ts       шифрование и подпись сообщений
src/lib/solana.ts         транзакции, чтение входящих, баланс, airdrop
src/lib/storage.ts        Keychain и AsyncStorage
src/state/messenger.tsx   состояние, отправка, синхронизация, блокировки
src/app/                  экраны (expo-router)
tests/                    vitest
```
